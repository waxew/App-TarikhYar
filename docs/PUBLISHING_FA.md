# راهنمای انتشار تاریخ‌یار

این سند روند انتشار امن نسخه‌های تاریخ‌یار را توضیح می‌دهد. نسخه فعلی مستندشده `1.6.0` با `versionCode 16` است.

## اصل حیاتی Signing

همه نسخه‌های بعدی باید با همان کلید Release دائمی تاریخ‌یار امضا شوند. اگر Certificate امضا عوض شود، Android اجازه نصب نسخه جدید روی نسخه قبلی را نمی‌دهد و مسیر Update قطع می‌شود.

کلید خصوصی، Keystore و Passwordهای Signing نباید در Repository عمومی، سورس ZIP یا فایل‌های معمول پروژه Commit شوند. برای شناسایی کلید صحیح، Fingerprintهای Certificate در `info.txt` بسته تحویلی ثبت می‌شوند و خود Keystore باید جداگانه در بکاپ امن نگهداری شود.

## چک‌لیست قبل از انتشار

1. `versionCode` افزایش پیدا کرده باشد.
2. `versionName` نسخه جدید را نشان دهد.
3. `version.json` با نسخه جدید هماهنگ باشد.
4. Unit Testها موفق باشند.
5. Release Build با `isDebuggable = false` ساخته شود.
6. APK با Certificate ثابت تاریخ‌یار امضا شود.
7. `apksigner verify` موفق باشد.
8. `zipalign` و هم‌ترازی 16KB بررسی شود.
9. APK روی Emulator یا دستگاه واقعی با `adb install -r` نصب شود.
10. `versionName` و `versionCode` نسخه نصب‌شده کنترل شوند.
11. سورس ZIP هیچ Keystore، Password یا Signing Material خصوصی نداشته باشد.

## GitHub Actions

Workflow عمومی مخزن فقط Build و Unit Test را انجام می‌دهد و به Signing Key دسترسی ندارد. Signing نسخه پابلیش باید در محیط انتشار کنترل‌شده انجام شود. اگر برای یک Release خاص Workflow موقت Signing استفاده شد، بعد از ساخت Artifact باید Workflow دوباره به حالت امن و فقط‌خواندنی برگردد.

## کافه‌بازار

برای انتشار عادی، APK/AAB رسمی امضاشده در پنل توسعه‌دهنده بارگذاری می‌شود. قابلیت‌های پرداخت درون‌برنامه‌ای در نسخه فعلی وجود ندارند. اگر در آینده Premium یا اشتراک اضافه شود، Provider پرداخت باید در لایه مستقل قرار گیرد و موتور تاریخ به SDK پرداخت وابسته نشود.

## Google Play

برای Google Play معمولاً AAB رسمی در Play Console بارگذاری می‌شود. در صورت استفاده از Play App Signing باید روند مهاجرت/ثبت کلید با دقت انجام شود تا مسیر بروزرسانی حفظ شود. فروش قابلیت‌های دیجیتال نیز باید مطابق قوانین جاری Google Play Billing پیاده‌سازی شود.

## نام فایل انتشار

فایل نهایی کاربر باید نام واضح نسخه داشته باشد و واژه‌هایی مانند `debug` یا `unsigned` در نام آن نباشد؛ نمونه: `TarikhYar-1.6.0.apk`.
