# راهنمای انتشار تاریخ‌یار 2.0

این سند روند انتشار امن تاریخ‌یار را توضیح می‌دهد. نسخه فعلی `2.0.0` با `versionCode 20` و Application ID ثابت `ir.tarikhyar.app` است.

## اصل حیاتی Signing
همه نسخه‌های بعدی باید با همان کلید Release دائمی تاریخ‌یار امضا شوند. تغییر Certificate یا Application ID باعث می‌شود Android نسخه جدید را Update نسخه نصب‌شده قبلی نداند.

Signing Key و Passwordها هرگز نباید در Repository عمومی GitHub Commit شوند. بسته خصوصی کامل تحویلی به مالک پروژه شامل پوشه `private-signing`، فایل JKS و اطلاعات لازم است؛ این بسته باید محرمانه نگهداری شود و نباید عمومی شود.

- SHA-1: `F4:02:39:3F:C6:82:AD:E6:E6:6B:92:E4:BD:9C:8C:6B:3E:12:70:66`

## چک‌لیست قبل از انتشار
1. `versionCode` نسبت به نسخه پابلیش قبلی افزایش پیدا کرده باشد.
2. `versionName` و `VERSION.txt` با نسخه جدید هماهنگ باشند.
3. `version.json` آخرین نسخه را اعلام کند.
4. استاندارد کامنت‌گذاری با `tools/apply_source_comments.py` قابل اعمال و Build باشد.
5. Unit Testها موفق باشند.
6. Release با `isDebuggable = false` ساخته شود.
7. APK/AAB با Certificate ثابت تاریخ‌یار امضا شود.
8. Signature و سلامت ZIP بررسی شود.
9. Native Libraryهای بدون فشرده‌سازی در صورت وجود 16KB alignment را حفظ کنند.
10. قبل از انتشار عمومی، نصب/Update روی حداقل یک دستگاه واقعی یا Emulator نهایی کنترل شود.

## GitHub Actions
Workflow عمومی مخزن Signing Key ندارد. CI ابتدا استاندارد کامنت‌گذاری را روی کپی Checkout اعمال می‌کند، سپس Unit Test و `assembleRelease` را اجرا می‌کند و APK بدون امضا را به‌عنوان Artifact نگه می‌دارد. Signing نهایی باید در محیط خصوصی انجام شود.

## بسته خصوصی مالک پروژه
ZIP خصوصی که به مالک تحویل داده می‌شود می‌تواند شامل JKS و اطلاعات Signing باشد، چون هدف آن Backup کامل پروژه است. این ZIP باید مثل Password یا کلید خصوصی نگهداری شود و نباید در GitHub، سایت عمومی یا پیام‌رسان عمومی قرار گیرد.

## کافه‌بازار
برای انتشار عادی، APK/AAB رسمی امضاشده در پنل توسعه‌دهنده بارگذاری می‌شود. اگر در آینده پرداخت درون‌برنامه‌ای اضافه شود، Provider پرداخت باید از موتور تقویم و داده‌های محلی جدا نگه داشته شود.

## نام فایل انتشار
فایل پابلیش باید نام نسخه داشته باشد و `debug` یا `unsigned` در نام آن نباشد؛ نمونه: `TarikhYar-2.0.0.apk`.
